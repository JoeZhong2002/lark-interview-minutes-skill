# 飞书专家访谈纪要

把逐字稿和访谈框架转成结构清晰、信息完整、含必要可视化的飞书云文档。最终交付必须是飞书链接，不以本地草稿代替。

## 输入要求

至少需要：

- 会议逐字稿：本地 `.docx`、`.txt`、`.md`，或用户直接粘贴的文字。
- 访谈框架：问题清单、研究框架或用户希望的纪要章节。

如果只缺访谈框架，先询问用户；若用户明确允许自由整理，则根据访谈主题建立框架。不要因个别字段缺失而停止可继续完成的工作。

## 工作流

### 1. 检查飞书依赖

先运行：

```bash
python3 scripts/check_dependencies.py
```

根据 JSON 结果处理：

- `ready=true`：进入步骤 2。
- 缺少 `larksuite/cli` 或官方飞书 Skills：向用户请求安装许可，获准后按 [依赖安装](references/dependency-install.md) 执行。
- 缺少 `design-lark-chart`：向用户请求安装许可，获准后从 `fuxiaoai/lark-chart-skill` 的 `skills/design-lark-chart` 安装。
- 安装 Skill 后提醒用户重启 Codex，再从本步骤续跑。
- 已安装但未配置/授权：按 `lark-shared` 的 split-flow 完成配置与 `docs,drive` 授权，不要让用户自己运行 device-code 回收命令。

不得跳过依赖检测，也不得未经同意安装软件。

### 2. 读取并规范化材料

- 完整抽取逐字稿中的段落、表格、说话人、时间戳和数字。
- 保留原始信息边界；自动转写疑点、专家推测、采访者提供的数据必须区分。
- 建立“访谈框架问题 → 原稿证据 → 回答状态”的内部映射。
- 不使用外部知识补造专家未提到的业务事实。

### 3. 三轮整理与回读

必须执行三轮，详见 [三轮整理规范](references/minutes-workflow.md)：

1. **框架轮**：严格按访谈框架整理初稿，覆盖专家提到的全部相关信息。
2. **补漏轮**：重新通读原稿，将第一次遗漏的信息放回对应章节。
3. **审计轮**：按时间轴再次回扫，检查数字、口径、冲突、推测、未回答项和框架外高价值信息。

没有完成三轮，不得创建最终飞书文档。

### 4. 选择可视化

逐章节判断是否适合图示。读取 [可视化选择](references/visualization-guide.md)。

原则：

- 可比较的重复字段用表格。
- 有阶段、时间或版本演进的信息用 Roadmap。
- 有流程、因果或角色协作的信息用流程图/泳道图。
- 有多分支归纳结构的信息用思维导图。
- 不适合图示化的正文保持文字原样，不为了“好看”重复表达。
- 已经清晰的原纪要结构和格式不做无关改动。
- 图中只能重组原稿信息，不得新增未经访谈支持的结论。

优先复用 `lark-doc` 原生表格和 Mermaid 画板；复杂图使用 `design-lark-chart`。每张图只讲一件事。

### 5. 创建飞书云文档

必须读取并遵守：

- `../lark-shared/SKILL.md`
- `../lark-doc/SKILL.md`
- 有画板时读取 `../lark-whiteboard/SKILL.md`
- 复杂或自由图示时读取 `../design-lark-chart/SKILL.md`

按 [飞书交付](references/lark-delivery.md) 执行：

1. 使用 XML 创建文档，保留纪要标题层级、表格、列表和注意事项。
2. 在对应章节插入表格或可编辑飞书画板。
3. 使用用户身份：`--as user`，API 固定为 `--api-version v2`。
4. 长文优先写入相对路径 XML 文件，再通过 `--content @文件.xml` 创建。
5. 返回飞书文档 URL。

### 6. 验收

创建后必须：

- `docs +fetch --scope outline` 回读目录，确认章节完整且顺序正确。
- 每张 Mermaid/PlantUML 画板用 `whiteboard +query --output_as code` 回读源码。
- 每张画板导出飞书真实预览图并视觉检查文字裁切、信息缺失、画布比例和可读性。
- 发现问题只修对应图或对应章节，不重写已清晰的其他内容。
- 最终只向用户交付飞书文档链接和简短变更说明。

## 失败处理

- 逐字稿无法读取：说明具体文件或格式问题，并尝试合适的文档读取 Skill。
- CLI 网络失败：对关键命令按原参数申请联网权限后重试。
- 钥匙串在沙箱不可用：解释安全权衡并征得同意后执行 `lark-cli config keychain-downgrade`。
- 图示回读失败：保留正文，修复或重建该画板；不得用本地图片冒充飞书画板验收结果。
- 未获得安装或授权同意：保留已完成的本地整理结果，明确说明飞书交付被阻塞。

## 触发示例

- “按照访谈提纲整理这份专家逐字稿，检查三遍并输出飞书纪要。”
- “把这份会议转写做成带流程图和 Roadmap 的飞书云文档。”
- “根据问题框架梳理所有专家观点，标出缺失信息和冲突口径。”
