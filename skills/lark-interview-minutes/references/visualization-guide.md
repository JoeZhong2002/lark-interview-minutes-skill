# 可视化选择

## 决策表

| 信息形态 | 首选形式 | 使用条件 |
|---|---|---|
| 多产品、多版本、多指标的重复字段 | 表格 | 至少 3 个共享字段，便于横向查阅 |
| 当前、Q3、年底、FY27、中期等阶段 | Roadmap | 时间或演进顺序是核心信息 |
| 先后步骤、整合过程、判断分支 | 流程图 | 关系比单点描述更重要 |
| 多角色协作与交接 | 泳道图 | 至少 2 个角色/系统且存在跨角色动作 |
| 中心主题及多个分支 | 思维导图 | 适合生态动作、问题归因、能力组成 |
| 层级、平台组成、产品定位关系 | 架构图 | 存在清晰上下层或依赖关系 |
| 简短警告、信息边界、待确认 | Callout | 不值得单独做图 |

## 不应图示化

- 一两句话已经能清楚说明。
- 图会与现有表格重复。
- 数字口径冲突且图会制造虚假精确性。
- 内容主要是免责声明、证据边界或待核实问题。
- 图中节点过多，无法“一张图讲一件事”。

## 图示要求

- 图示只重组逐字稿信息，不新增业务模块。
- 标题直接说明图的结论或用途。
- Mermaid 适合流程图、Roadmap、思维导图、时序图和甘特图。
- 表格使用飞书文档原生 `<table>`。
- 强视觉架构图、复杂泳道图或自由图使用 `design-lark-chart`。
- 图示完成后必须回读源码并导出真实飞书预览图。
- 若 Roadmap 被渲染成过高纵向画布，改用“阶段为列、产品为行”的横向布局。
